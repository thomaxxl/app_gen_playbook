# Remarks

This file is intentionally neutral until a new run starts.

Use local `runs/current/remarks.md` only for curated playbook feedback and
improvement notes, for example:

- orchestrator-detected control-plane defects such as invalid handoffs,
  routing failures, or dead-end stalls
- documented ambiguities in playbook instructions, contracts, or ownership
- durable process improvements promoted out of ad hoc role-specific notes

Ordinary runtime-role observations, verification results, CEO approval notes,
stale-blocker repetition, and other run-specific events belong in
`runs/current/notes.md`, role-owned artifacts, evidence files, or
`runs/current/remarks-events.jsonl` instead.
